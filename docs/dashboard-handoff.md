> **به مدل جدید:** قبل از هر تغییری `index.html` رو از روی شاخه‌ی `main` بخون — کد مرجع نهاییه؛ این فایل فقط نقشه‌ست.

### خوندن شیت‌ها
- مرورگر `GET /api/sheet-data?spreadsheetId=…&sheet=…` رو صدا می‌زنه. تابع Vercel با **Service Account** گوگل (متغیرهای محیطی `GOOGLE_SERVICE_ACCOUNT_EMAIL` و `GOOGLE_PRIVATE_KEY`) از Sheets API v4 می‌خونه (`valueRenderOption=UNFORMATTED_VALUE`، بازه‌ی `A:Z`).
- فقط شیت‌هایی که تو `ALLOWED_SPREADSHEETS` داخل `api/sheet-data.js` هستن خونده می‌شن.
- **اضافه کردن پروژه‌ی جدید =** (۱) یه آبجکت تو `ALL_PROJECTS` داخل `index.html`، (۲) اضافه کردن `spreadsheetId` به `ALLOWED_SPREADSHEETS`، (۳) شیر کردن شیت با ایمیل Service Account (این کار با عرفانه؛ از داخل چت قابل چک نیست).

### روال دیپلوی
1. تغییر روی شاخه‌ی کار → commit → push.
2. `git fetch origin main` — **مهم:** عرفان گاهی مستقیم از وب گیت‌هاب فایل (معمولاً لوگو) رو `main` آپلود یا حذف می‌کنه، پس `main` ممکنه جلو افتاده باشه. اگه جلو بود، اول `origin/main` رو تو شاخه‌ی کار merge (یا fast-forward) کن و دوباره تست کن.
3. `git push origin HEAD:main` → Vercel خودش دیپلوی می‌کنه.
4. **بعد از push حتماً وضعیت دیپلوی Production رو چک کن:** `gh api repos/erfanhamedi7-marketer/yektanet-pulse-dashboard/commits/<sha>/statuses` (یا `/deployments` + `/deployments/<id>/statuses`). ۱۱ اکتبر دیپلوی Production کامیت `0dab1b1` بی‌صدا fail شد (Preview همون کامیت موفق بود) و سایت روی نسخه‌ی قبلی موند؛ با یه کامیت تازه دوباره دیپلوی شد. لاگ Vercel از اینجا قابل دیدن نیست (MCP ورسل به تیم `erfan-s` دسترسی نداره).

## ۲. معماری کد (`index.html`)

- **تنظیمات پروژه‌ها:** آرایه‌ی `ALL_PROJECTS`؛ `PROJECTS = ALL_PROJECTS.filter(p => !p.hidden)`. بخش‌ها با تابع‌ها ساخته می‌شن: `snappSections()`، `arzplusSections()` (+ `webSection` و `ramzarzSection()`)، `yektanetExportSections()` (فیروزه/تارا/تکنوپی)، `talaseaSections()` (طلاسی).
- **تب‌ها:** پروژه‌هایی که `group` مشترک دارن پشت یک تب می‌رن (`groupTitle` اسم تب، `partTitle` اسم زیرتب). پروژه‌ی تکی: `tabTitle`.
- **ترتیب تب‌ها:** شهر لوازم خانگی، اسنپ، طلاین، ویپاد، بلو، بانکینو، ارزپلاس، فیروزه، تارا، تکنوپی، طلاسی، آگاه. (۲۹ سکشن در کل.)
- **زیرتب‌های ارزپلاس:** ارزپلاس - اپلیکیشن، ارزپلاس - کافه بازار، ارزپلاس - وب، توچال - اپلیکیشن، توچال - کافه بازار، توچال - وب، رمزارز نیوز.
- **مدل جوین:** ردیف‌های تبدیل (شیت مرجع/ref) با ردیف‌های هزینه روی `تاریخ + کمپین` جوین می‌شن. اسم کمپین نرمال می‌شه (trim + lowercase)، تاریخ به `YYYYMMDD`. عدد و تاریخ با parser مقاوم خونده می‌شن (ارقام فارسی، جداکننده‌ها، نماد علمی، شماره‌سریال تاریخ Sheets، `M/D/YYYY`).
- **سه نوع سکشن:**
  - معمولی (هزینه + تبدیل + CPA + تحلیل عمیق) — `updateSection`
  - `kind:'budget'` (اسنپ‌ها) — `updateBudgetSection`
  - `kind:'cpi'` (رمزارز نیوز) — `updateCpiSection`
- **هر تغییر فیلتر از `updateSection` رد می‌شه**؛ همونجا لیست‌های فیلتر (`renderCampaignDropdown`) و چیپ‌های فیلتر Adgroup/Creative (`renderSegChips`) هم به‌روز می‌شن.
- **فقط سکشنِ روی صفحه رسم می‌شه (از ۲۱ اکتبر):** `updateSection` اگه سکشن باز نباشه فقط `project.stale = true` می‌زنه؛ `switchTab` موقع باز کردن سکشن `drawSection` رو صدا می‌زنه. رسم واقعی تو `drawSection`ه. پس هیچ کدی نباید فرض کنه DOM سکشن‌های بسته به‌روزه. قبلاً هر ۲۸ سکشن موقع لود (دوبار) رسم می‌شدن و کارت‌هاشون اندازه‌گیری می‌شد؛ لود تو تست ۱۳.۷ ثانیه → ۳ ثانیه شد.

| گزینه | کارش |

| `rowFilter(row)` | قبل از هر چیزی ردیف خام شیت رو (هم مرجع هم هزینه) فیلتر می‌کنه. مثلاً `advertiserIs('65519')` برای Advertiser ID |

| `showInstalls`, `installsCol`, `installsLabel`, `adgroupCol`, `creativeCol`, `impressionsCol`, `clicksCol` | ستون‌ها |
| `costPerMetrics` | کارت‌های «هزینه به ازای X» برای ستون‌های اضافه‌ی شیت مرجع: `{col, label, sinceFirst, campaignTable, countCard, noRate}`. `sinceFirst` = هزینه فقط از اولین روزی که این ستون پر شده حساب بشه (Signup رمزارز). `campaignTable` = تعداد/نرخ/هزینه به ازاش تو جدول کمپین هم بیاد. `countCard` = تعداد یه کارت جدا داشته باشه. `noRate` = ستون نرخ (X ÷ تبدیل اصلی) تو جدول نیاد (CTA Click آگاه) |

| `hideZeroConversionCampaigns` | کمپینی که تو بازه‌ی انتخابی تبدیل اصلیش صفره (با هزینه‌ش) کلاً حذف بشه؛ لیست فیلتر هم فقط کمپین‌هایی که یه‌بار تبدیل داشتن رو نشون می‌ده (آگاه) |
| `refCampaignCol` | اسم ستون کمپین تو شیت مرجع (پیش‌فرض `Campaign`؛ آگاه `Ad Term`) |
| `compareConversion` | همون تبدیل از یه منبع دوم برای مقایسه: `{sheet, col, source, ownSource, campaignCol?}` (GA4 تکنوپی؛ `campaignCol` پیش‌فرض `Campaign`ه، آگاه `Ad Term`). کارت + ستون و درصد اختلاف (منبع دوم − منبع اصلی) ÷ منبع اصلی |
| `dimensionTables` | جدول‌های Source/Term/Content (بعد + متریک) — کارتش پیش‌فرض بسته‌ست و هر جدول فیلتر خودش رو داره |
| `sessionsCompare` | مقایسه‌ی سشن با تب دیگه (GA4) |
| `cpiGroups` | گروه‌های نمودار در سکشن CPI |
| `defaultCampaigns` | فیلتر پیش‌فرض کمپین (اسم دقیق؛ اسمی که تو شیت نباشه بی‌صدا نادیده گرفته می‌شه) |
| `messageHide` | خط‌هایی که متن گزارش مشتری نباید بیاره، مثلاً `['clicks']` (آگاه) |
| `logo`, `logoWide`, `theme` | ظاهر (`theme` از `BRANDS`) |
| `hidden` | پروژه اصلاً لود نمی‌شه |

## ۴. قابلیت‌های سراسری

### تاریخ
- **امروز هیچ‌وقت حساب نمی‌شه.** ردیف‌های امروز و آینده موقع لود حذف می‌شن و حداکثر تاریخ دیروزه.
- پریست‌ها: **کل بازه | دیروز | از شنبه | ۷ روز اخیر | ۳۰ روز اخیر**.
- «از شنبه» اگه امروز شنبه باشه، از **شنبه‌ی قبل** تا دیروز رو نشون می‌ده — یعنی روز شنبه با «۷ روز اخیر» یکیه (عرفان یه بار فکر کرد خرابه؛ بررسی شد و درست کار می‌کرد).
- تاریخ‌ها با تاریخ محلی ساخته می‌شن (`localIso`)، نه `toISOString`.

### فیلتر کمپین
- چندانتخابی، با **نوار جست‌وجو**؛ تو حالت جست‌وجو، تیک «همه» دقیقاً همون موارد منطبق رو انتخاب می‌کنه.
- **لیست‌ها از بقیه‌ی فیلترها پیروی می‌کنن** (`slotScope` / `scopedOptions`): لیست کمپین فقط کمپین‌های دارای دیتا در بازه‌ی تاریخ رو نشون می‌ده، مرتب بر اساس هزینه‌ی همون بازه (عدد کنار هر کمپین = هزینه‌ی بازه). اسنپ: دو لیست همدیگه رو فیلتر می‌کنن.
  - انتخاب‌ها نسبت به **کل** کمپین‌ها (`universe`) نگه داشته می‌شن؛ محدود شدن لیست انتخاب رو عوض نمی‌کنه.
  - کمپینی که دستی انتخاب شده (انتخاب ≤ نصف لیست) حتی بیرون از بازه تو لیست می‌مونه؛ انتخاب‌های «همه به‌جز چندتا» این‌طور نیستن.
- اسم کمپین تو جدول‌ها **کلیک‌پذیره** و داشبورد رو با همون کمپین فیلتر می‌کنه (کلیک دوباره = برداشتن فیلتر).

### فیلتر Adgroup / Creative (۶ اکتبر)
- کلیک روی اسم Adgroup یا Creative تو جدول‌هاش، **کل سکشن** رو روی همون فیلتر می‌کنه (کارت‌ها، نمودار، جدول کمپین، جدول دیگه)؛ کلیک دوباره برمی‌داره. Adgroup و Creative با هم ترکیب می‌شن.
- فیلترهای فعال به‌صورت **چیپ** بالای کارت‌ها: «فیلتر: Adgroup: … ✕».
- هزینه چون فقط سطح کمپینه، **هزینه‌ی روزانه‌ی هر کمپین به نسبت نصب همون روز** بین Adgroup/Creativeها تقسیم می‌شه (`applySegFilter`). با یه مثال عدد به عدد با شیت چک شد.
- رمزارز نیوز: جدول کریتیو هم همین‌طوره.

### کپی اسم

### جدول‌ها
- **همه‌ی جدول‌ها ردیف «مجموع» دارن.** شمارش‌ها و هزینه جمع می‌شن؛ CPA/CPI/هزینه به ازا/نرخ‌ها = **نرخ ترکیبی** (هزینه‌ی کل ÷ تبدیل کل)، نه میانگین ردیف‌ها.
- **جدول کمپین:** ۱۲ ردیف اول + دکمه‌ی «نمایش همه‌ی N کمپین» / «فقط ۱۲ کمپین اول». مجموع همیشه همه‌ی کمپین‌ها رو حساب می‌کنه.
- **جدول‌های Adgroup / Creative** (عنوان: «CPA Adgroup‌ها و Creative‌ها»):
  - **همه‌ی موارد با نصب و هزینه‌ی قابل‌توجه** (حداقل max(۵، ۰.۱٪ نصب‌ها) نصب و ۰.۱٪ هزینه)، نه فقط گرون‌ترها.
  - **مرتب‌سازی مثل قبل:** اول «بدون تبدیل»‌ها (به ترتیب هزینه)، بعد CPA نزولی.
  - ۲۵ ردیف اول + دکمه‌ی «نمایش همه». مجموع روی همه‌ی موارد.

### متن گزارش برای مشتری — `index.html` (از ۲۵ اکتبر)
- ته هر سکشن داشبورد اصلی یه کارت «متن گزارش برای مشتری» هست: textarea قابل‌ویرایش + دکمه‌ی «کپی متن» (`copyText`: اول clipboard API، اگه رد شد `execCommand`). متن با هر رسم سکشن (`drawSection` → `renderClientMessage`) از نو ساخته می‌شه و ویرایش دستی رو پاک می‌کنه. `report.html` این کارت رو **نداره**.
- **قالب عرفان** (`buildClientMessage`): «سلام وقتتون بخیر» / «گزارش هفته پیش خدمت شما» (۱ روز: «گزارش دیروز…»، بقیه: «گزارش این بازه…») / بازه به شمسی بدون سال «(۲۶ مهر تا ۲ آبان)» / «مجموع» + خط‌ها / بعد برای هر گروه نوع کمپین «کمپین‌های X:» + همون خط‌ها / جمله‌ی مقایسه با بازه‌ی هم‌طول قبلی (`previousWindow`): «در هفته‌ی گذشته نسبت به هفته‌ی قبلش تعداد اکشن از A به B رسید و هزینه به ازای اکشن هم از C به D رسید.» (اگه یه طرف هزینه نداشت، نیمه‌ی دوم نمیاد). عددها با ارقام فارسی و جداکننده‌ی `,`، بدون «تومان»، مثل قالب.
- **خط‌ها** (`messageLines`): هزینه، نمایش، کلیک، نرخ CTR، تعداد سشن، نرخ STC، تعداد نصب، هزینه به ازای نصب، تعداد اکشن مدنظر، هزینه به ازای اکشن مدنظر. **خطی که کسب‌وکار اصلاً دیتاش رو نداره نمیاد** (`messageFields`: روی کل دیتای لودشده، نه فقط بازه؛ پس هفته‌ی بی‌دیتا ۰ نشون می‌ده). بعد از CTR/STC یه RLM (`‏`) هست وگرنه «٪» می‌پره قبل از CTR.
- **از کجا خونده می‌شن** (`messageSpec`): نمایش/کلیک از شیت هزینه (`impressions`/`clicks` حالا تو ردیف‌های join هم هستن). سشن: تبدیل اصلی اگه Sessions باشه (آگاه)، یا ستون «نصب» اگه Sessions باشه (شهر، فیروزه، تارا، تکنوپی)، یا Sessions شیت Blend Data (اسنپ‌ها). نصب: ستون نصب واقعی (Total Installs / Installs) یا تبدیل اصلی رمزارز. اکشن مدنظر: تبدیل اصلی؛ ولی اگه تبدیل اصلی سشن یا نصب باشه، اولین `costPerMetrics` (آگاه: CTA Click، رمزارز: Signup). اسنپ‌ها اکشن ندارن و جمله‌ی مقایسه روی سشنه. آگاه با `messageHide: ['clicks']` کلیک تبلیغ (و CTR و STC) رو نمیاره، هم‌راستا با داشبوردش.
- **گروه‌های نوع کمپین** فقط از ستون `Campaign Type` شیت هزینه میاد (`normalizeCostRows` → `type`؛ `campaignTypeGroup`: اپلیکیشن → درون‌اپلیکیشنی، پویا/native → پویا، همسان، ویدیویی، پوش، پیامکی، پیام روبیکا، بنری). فقط **فیروزه، تارا، تکنوپی و آگاه** این ستون رو دارن؛ بقیه فقط «مجموع» دارن. گروه وقتی میاد که بازه حداقل دو نوع داشته باشه. برای بقیه، ستون Campaign Type باید به خروجی متابیس / `process.py` اون شیت‌ها اضافه بشه.
- چک‌شده با Python روی شیت (۱۸ تا ۲۴ اکتبر): تکنوپی (هزینه، نمایش، کلیک، سشن، Validation، و هفته‌ی قبل)، طلاین وب (هزینه، نمایش، کلیک).

### گزارش هفتگی برای مشتری — `report.html` (از ۲۵ اکتبر)
- **یه کپی کامل از `index.html`ه** (از کامیت `beaddd3`)، با عنوان «Weekly Report». تغییرهای بعدی `index.html` **خودکار به اینجا نمیاد**؛ اگه یه تغییر داشبورد (پروژه، قانون، رفع باگ) باید تو گزارش هم باشه، تو هر دو فایل اعمالش کن. عرفان گفته به‌مرور می‌گه هر گزارش چی کم یا زیاد داشته باشه؛ این تغییرها فقط تو `report.html` می‌رن.
- دکمه‌های **خروجی PDF** و **خروجی HTML** بالای هر سکشن کنار فیلتر کمپینن (`.report-actions` داخل `.section-controls`). **کارت «توضیحات» ته سکشنه**: textarea (ذخیره تو `localStorage` با کلید `reportNotes:<id>`، فقط همون مرورگر).
- **قانون عرفان (۲۵ اکتبر): فرمت خروجی باید دقیقاً همون داشبورد باشه** — نسخه‌ی اول یه چیدمان جدا (سفید، کارت‌های ۳تایی، نمودار جدا) داشت و عرفان گفت «کلا بهم ریخته». الان خروجی (`reportSectionHtml`) **کلون خود سکشن بازه** با کل CSS صفحه و استایل `html` (رنگ صفحه): کارت‌ها، نمودار، تحلیل عمیق و جدول‌ها همون‌طور که رو صفحه‌ان. فقط این‌ها حذف می‌شن: فیلترها و دکمه‌ها، «?»ها، کارت‌های بسته (Source/Term/Content)، باکس توضیحات. نمودارها عکس PNG می‌شن (`chartImage`: `devicePixelRatio` بالا، پس‌زمینه‌ی سفید) و تو همون `.chart-box` می‌شینن. اسم کمپین‌ها (دکمه‌ی فیلتر) `span` می‌شن. جدول‌ها کامل (بدون اسکرول عمودی). متن توضیحات به‌صورت یه کارت «توضیحات» آخر از همه میاد (پاراگراف با خط خالی).
- **جلد** (صفحه‌ی اول، چیزی که عرفان اول خواست): لوگوی برند (data URL)، «گزارش عملکرد کمپین‌ها»، اسم پروژه، بازه به شمسی (`fa-IR-u-ca-persian`) و میلادی، فیلتر کمپین اگه «همه» نباشه، تاریخ تهیه.
- خروجی همون چیزیه که رو صفحه‌ست: بازه، فیلتر کمپین و متریک‌هایی که رو نمودار انتخاب شدن.
- HTML = دانلود Blob (`<id>-report-<from>-<to>.html`)، با یه اسکریپت کوچیک (`fitKpiValues`) که عددهای کارت رو برای عرض پنجره (و قبل از چاپ) دوباره کامل/مخفف می‌کنه؛ فونت از Google Fonts. PDF = همون سند تو یه iframe مخفی **۱۰۶۲px** و `print()` مرورگر (Save as PDF). `@media print`: **A4 افقی** با حاشیه‌ی ۸mm، یعنی ۱۰۶۲px عرض — بیشتر از ۹۰۰px، پس قانون‌های موبایل/تبلت فعال نمی‌شن و PDF چیدمان دسکتاپ داره (A4 عمودی ~۷۱۸px بود و چیدمان موبایلی می‌شد). جلد ۱۸۵mm با `break-after:page`. جدول‌ها تو چاپ فونت ۱۰px و تیتر چندخطی تا همه‌ی ستون‌ها تو صفحه جا شن. اسم PDF از `document.title` میاد که موقع چاپ موقتاً اسم فایل می‌شه.
- تست: کلیک `a.download` رو stub کن (وگرنه فایل واقعاً دانلود می‌شه) و `print` iframe رو با MutationObserver روی `load` عوض کن. برای دیدن چیدمان چاپ، `@media print{` رو به `@media all{` تبدیل کن و تو پنجره‌ی 1062×699 ببین. هشدار: کارت «هزینه به ازای سشن» آگاه تو عرض ~۱۰۰۰px «تومان» رو با «…» می‌بره — خود داشبورد هم همینه، ربطی به خروجی نداره.

## ۶. نکات فنی و تله‌ها

- **`[hidden]` با `display:flex` کار نمی‌کنه:** قانون صریح `X[hidden]{display:none}` لازمه.
- `transform` روی المان inline کار نمی‌کنه (فلش دکمه‌ی بستن) → `display:inline-block`.
- `renderKpiCards` تعداد ستون‌ها رو inline می‌نویسه، پس مدیا کوئری موبایل `!important` لازم داره.
- متن ترکیبی فارسی/لاتین با درصد (مثل «اختلاف با یکتانت: +12٪») ترتیبش به هم می‌ریزه → `<bdi dir="ltr">` دور عدد، و اسم منبع فارسی.
- اسم‌های فارسی رو با فونت mono نشون نده. IBM Plex Mono حروف فارسی نداره؛ از ۹ اکتبر `--font-mono` بعدش `Vazirmatn` داره تا «تومان» و متن فارسی داخل عددها از هم باز نشه. ولی باز هم متن فارسی رو عمداً mono نکن.
- **عدد علامت‌دار وسط متن فارسی** علامتش می‌پره اون‌ور («12-»). برای `+`/`−` از `fmtSigned(n)` استفاده کن (خروجیش `<bdi dir="ltr">`ه)؛ عدد کارت‌های KPI هم تو `kpiValueHtml` با `<bdi>` ایزوله شده. `.di-tag` چون `inline-flex`ه فاصله‌ها رو می‌خوره — `gap` داره.
- **اسم ستون نمایش/کلیک فرق داره:** `Cost - Yektanet` طلاین، `Yektanet` بلو و بلو جونیور و تب‌های طلاسی `Impressions`/`Clicks` (جمع) دارن؛ بقیه `Impression`/`Click`. طلاین و بلو جونیور تا ۲۵ اکتبر اشتباهی مفرد تنظیم شده بودن (جایی نمایش داده نمی‌شد پس دیده نشد)؛ با متن گزارش مشتری درست شدن.
- اسم تب‌های شیت دقیق‌ان: `Arzplus- Yektanet` و `Ramzarz- Yektanet` قبل از خط تیره فاصله ندارن. توچال `Tocal` نوشته شده.
- لیست فیلتر کمپین، بدون `includeUnmatchedCost`، فقط کمپین‌های طرف تبدیل رو نشون می‌ده؛ و جدول کمپین هزینه‌ی یه کمپین رو فقط روزهایی که ردیف تبدیل داره حساب می‌کنه (مثلاً `cb-dc-rtg` تو ۷ روز اخیر نیومد چون App Metrica ردیف نداشت).
- **`/api/sheet-data`:** جواب فشرده‌ست: `{headers, rows}` (ردیف‌ها آرایه، ردیف‌های کاملاً خالی حذف). **از ۲۴ اکتبر چند تب با هم:** `sheet` تکراری (`?spreadsheetId=…&sheet=A&sheet=B`) → `{sheets: {A: {headers, rows}, B: …}}`، با یه `values:batchGet` (گوگل یه درخواست حساب می‌کنه). یه `sheet` → همون `{headers, rows}`. `fetchSheetData` تو مرورگر درخواست‌های همون لحظه رو برای هر اسپردشیت جمع می‌کنه (`sheetQueue`/`flushSheetQueue`) و `sheetRows` فرمت قدیمی `{data}` رو هم قبول می‌کنه (mockهای تست). کش لبه‌ی Vercel: `s-maxage=300, stale-while-revalidate=1800` — تغییر شیت حداکثر حدود ۵ دقیقه بعد دیده می‌شه. هر نمونه‌ی گرم تابع هم ۲ دقیقه کش حافظه داره (`memo`) و موقع خطای سهمیه تا ۲۴ ساعت نسخه‌ی قبلی رو برمی‌گردونه.
- **سهمیه‌ی Google Sheets API:** ۶۰ درخواست خوندن در دقیقه برای Service Account. قبلاً هر لود ~۳۸ درخواست بود و با دو سه بار رفرش (یا بعد از هر دیپلوی که کش لبه رو خالی می‌کنه) خطای `Quota exceeded … Read requests per minute per user` می‌داد؛ الان هر لود ۱۹ درخواسته (یکی به ازای هر اسپردشیت + تب‌های Source/Term/Content). API روی 429 دو بار دیگه (۱.۵ و ۳ ثانیه بعد) تلاش می‌کنه و بعد `{code:'quota'}` با 429 برمی‌گردونه؛ سکشن پیام «سهمیه‌ی خوندن گوگل شیت پر شده — رفرش کن» نشون می‌ده نه «شیت رو شیر کن». اگه یه تب از یه اسپردشیت خطا بده، همه‌ی تب‌های اون اسپردشیت تو همون لود خطا می‌گیرن.
- `fmtNum` فرمت‌کننده‌ی `Intl.NumberFormat` رو کش می‌کنه (`toLocaleString` هر بار یه فرمت‌کننده‌ی تازه می‌ساخت). انیمیشن Chart.js ۳۰۰ میلی‌ثانیه‌ست (`makeChart`). `fitKpiValues` اندازه‌گیری‌ها رو دسته‌ای انجام می‌ده.
- **محیط ابری:** به `docs.google.com`، `cdnjs` و `*.vercel.app` دسترسی نیست (پروکسی می‌بنده). سایت زنده قابل تست نیست. شیت‌ها با **Google Drive MCP** خونده می‌شن: `download_file_content` با `exportMimeType` xlsx → فایل base64 تو tool-results → decode و با `openpyxl` بخون. `read_file_content` برای شیت‌های کوچک کافیه؛ `get_file_metadata` با `MAX_ALLOWED` برای دیدن اسم تب‌ها و هدرها (خالی‌ها رو حذف می‌کنه).
- **روش تست:**
  - اسکریپت بزرگ HTML رو جدا کن → `node --check`.
  - Chart.js رو با `npm pack chart.js@4.4.1` بگیر (npm در دسترسه).
  - Playwright (`/opt/node-tools/node_modules/playwright`، Chromium در `/opt/pw-browsers/chromium`) روی `python3 -m http.server 8765`.
  - `**/api/sheet-data*` با `mock.json` (کلید `spreadsheetId||sheet`، ساخته‌شده از xlsx واقعی) جواب داده می‌شه؛ cdnjs با فایل محلی؛ فونت‌ها abort.
  - `timezoneId:'Asia/Tehran'` و `page.clock.install` برای تست تاریخ‌ها.
  - کپی: `navigator.clipboard` رو stub کن.
  - برای قوانین جدید، جواب درست رو جدا با Python از xlsx حساب کن و عدد به عدد مقایسه کن.
  - رگرسیون: هر ۲۸ سکشن رندر بشن، بدون خطای صفحه، دسکتاپ (1400) و موبایل (390). چون سکشن‌ها فقط وقتی باز می‌شن رسم می‌شن، تست باید روی تک‌تک تب‌ها و زیرتب‌ها کلیک کنه و بعد متن سکشن رو بخونه.
