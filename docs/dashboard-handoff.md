# Management Dashboard — راهنمای ادامه‌ی کار (Handoff)

> این فایل خلاصه‌ی کامل تاریخچه، معماری، قوانین کسب‌وکاری و سلیقه‌های طراحی داشبوردیه که تا ۶ اکتبر ۲۰۲۶ ساخته شده (آخرین به‌روزرسانی: ۲۸ اکتبر ۲۰۲۶ — طلاین: Web - Total و CPA جدید).
> توی چت جدید اول این فایل رو بده، بعد ادیت‌هات رو بگو.
> **به مدل جدید:** قبل از هر تغییری `index.html` رو از روی شاخه‌ی `main` بخون — کد مرجع نهاییه؛ این فایل فقط نقشه‌ست.
> **جای این فایل:** `docs/dashboard-handoff.md` توی ریپو. هر تغییر اثرگذار (پروژه/قانون/قابلیت/طراحی/تله‌ی فنی جدید) باید تو همون کامیت اینجا هم ثبت بشه — قاعده‌اش تو `CLAUDE.md` ریشه‌ی ریپوئه.

### خوندن شیت‌ها
- مرورگر `GET /api/sheet-data?spreadsheetId=…&sheet=…` رو صدا می‌زنه. تابع Vercel با **Service Account** گوگل (متغیرهای محیطی `GOOGLE_SERVICE_ACCOUNT_EMAIL` و `GOOGLE_PRIVATE_KEY`) از Sheets API v4 می‌خونه (`valueRenderOption=UNFORMATTED_VALUE`، بازه‌ی `A:Z`).
- فقط شیت‌هایی که تو `ALLOWED_SPREADSHEETS` داخل `api/sheet-data.js` هستن خونده می‌شن.
- **اضافه کردن پروژه‌ی جدید =** (۱) یه آبجکت تو `ALL_PROJECTS` داخل `index.html`، (۲) اضافه کردن `spreadsheetId` به `ALLOWED_SPREADSHEETS`، (۳) شیر کردن شیت با ایمیل Service Account (این کار با عرفانه؛ از داخل چت قابل چک نیست).

### ورود (لاگین) — از ۲۶ اکتبر
- هر سه صفحه (`index.html`، `report.html` و `slides.html`) اول `/auth.js` رو لود می‌کنن: صفحه تا وقتی سرور تأیید نکنه کسی وارد شده پنهانه و فرم ورود (نام کاربری + رمز) نشون داده می‌شه؛ بعد از ورود `window.dashAuth.ready().then(init)` داشبورد رو شروع می‌کنه. کنار وضعیت همگام‌سازی اسم کاربر + دکمه‌ی «خروج» میاد (رو گوشی فقط «خروج»).
- **قفل واقعی سمت سروره:** `api/sheet-data.js` بدون نشست معتبر 401 می‌ده. اگه وسط کار نشست تموم بشه، صفحه رفرش می‌شه و دوباره فرم ورود میاد.
- **حساب‌ها:** متغیر محیطی `DASHBOARD_USERS` تو Vercel، به شکل `erfan:رمز,ali:رمز2` (کاما یا خط جدید بین حساب‌ها؛ نام کاربری حساس به حروف بزرگ/کوچیک نیست). اضافه/حذف/عوض کردن رمز = ویرایش همین متغیر + Redeploy. عوض شدن رمز یا حذف حساب، اون آدم رو همه‌جا خارج می‌کنه.
- **بدون `DASHBOARD_USERS` هیچ‌کس وارد نمی‌شه** (fail-closed؛ `/api/me` و `/api/login` 503 و فرم پیام «ورود روی سرور تنظیم نشده» می‌ده). پس قبل از دیپلوی تغییری که ورود رو لازم داره، متغیر باید ست شده باشه.
- نشست: کوکی `md_session` (HttpOnly، Secure، SameSite=Lax، ۳۰ روز) امضاشده با HMAC؛ کلید امضا `AUTH_SECRET` اگه باشه، وگرنه از `GOOGLE_PRIVATE_KEY` مشتق می‌شه. رمز اشتباه ۱ ثانیه تأخیر داره.
- فایل‌ها: `api/_auth.js` (منطق مشترک؛ `_` یعنی Vercel ازش endpoint نمی‌سازه)، `api/login.js` (POST)، `api/logout.js`، `api/me.js`، `auth.js` (فرم و چیپ کاربر). نسخه‌ی HTML خروجی گزارش برای مشتری (دیتای جاسازی‌شده) ورود نمی‌خواد.
- کد HTML/JS صفحه هنوز بدون ورود قابل دیدنه (فقط دیتا قفله)؛ برای قفل کردن خود صفحه هم Vercel Routing Middleware لازمه (انجام نشده).
- **تست محلی:** یه سرور Node کوچیک که فایل‌های `api/*.js` رو مثل Vercel اجرا می‌کنه (`req.query`، `req.body`، `res.status().json()`) با `google-auth-library` جعلی؛ Playwright فرم، رمز اشتباه، ورود، رفرش، خروج رو چک می‌کنه.

### روال دیپلوی
1. تغییر روی شاخه‌ی کار → commit → push.
2. `git fetch origin main` — **مهم:** عرفان گاهی مستقیم از وب گیت‌هاب فایل (معمولاً لوگو) رو `main` آپلود یا حذف می‌کنه، پس `main` ممکنه جلو افتاده باشه. اگه جلو بود، اول `origin/main` رو تو شاخه‌ی کار merge (یا fast-forward) کن و دوباره تست کن.
3. `git push origin HEAD:main` → Vercel خودش دیپلوی می‌کنه.
4. **بعد از push حتماً وضعیت دیپلوی Production رو چک کن:** `gh api repos/erfanhamedi7-marketer/yektanet-pulse-dashboard/commits/<sha>/statuses` (یا `/deployments` + `/deployments/<id>/statuses`). ۱۱ اکتبر دیپلوی Production کامیت `0dab1b1` بی‌صدا fail شد (Preview همون کامیت موفق بود) و سایت روی نسخه‌ی قبلی موند؛ با یه کامیت تازه دوباره دیپلوی شد. لاگ Vercel از اینجا قابل دیدن نیست (MCP ورسل به تیم `erfan-s` دسترسی نداره).

## ۲. معماری کد (`index.html`)

- **تنظیمات پروژه‌ها:** آرایه‌ی `ALL_PROJECTS`؛ `PROJECTS = ALL_PROJECTS.filter(p => !p.hidden)`. بخش‌ها با تابع‌ها ساخته می‌شن: `snappSections()`، `arzplusSections()` (+ `webSection` و `ramzarzSection()`)، `yektanetExportSections()` (فیروزه/تارا/تکنوپی)، `talaseaSections()` (طلاسی).
- **تب‌ها:** پروژه‌هایی که `group` مشترک دارن پشت یک تب می‌رن (`groupTitle` اسم تب، `partTitle` اسم زیرتب). پروژه‌ی تکی: `tabTitle`.
- **ترتیب تب‌ها:** شهر لوازم خانگی، اسنپ، طلاین، ویپاد، بلو، بانکینو، ارزپلاس، فیروزه، تارا، تکنوپی، طلاسی، آگاه. (۳۱ سکشن در کل؛ `report.html` هنوز ۲۹ تا، بدون اپ طلاسی/نقره‌سی.)
- **زیرتب‌های ارزپلاس:** ارزپلاس - اپلیکیشن، ارزپلاس - کافه بازار، ارزپلاس - وب، توچال - اپلیکیشن، توچال - کافه بازار، توچال - وب، رمزارز نیوز.
- **مدل جوین:** ردیف‌های تبدیل (شیت مرجع/ref) با ردیف‌های هزینه روی `تاریخ + کمپین` جوین می‌شن. اسم کمپین نرمال می‌شه (trim + lowercase)، تاریخ به `YYYYMMDD`. عدد و تاریخ با parser مقاوم خونده می‌شن (ارقام فارسی، جداکننده‌ها، نماد علمی، شماره‌سریال تاریخ Sheets، `M/D/YYYY`).
- **سه نوع سکشن:**
  - معمولی (هزینه + تبدیل + CPA + تحلیل عمیق) — `updateSection`
  - `kind:'budget'` (اسنپ‌ها) — `updateBudgetSection`
  - `kind:'cpi'` (رمزارز نیوز) — `updateCpiSection`
- **هر تغییر فیلتر از `updateSection` رد می‌شه**؛ همونجا لیست‌های فیلتر (`renderCampaignDropdown`) و چیپ‌های فیلتر Adgroup/Creative (`renderSegChips`) هم به‌روز می‌شن.
- **فقط سکشنِ روی صفحه رسم می‌شه (از ۲۱ اکتبر):** `updateSection` اگه سکشن باز نباشه فقط `project.stale = true` می‌زنه؛ `switchTab` موقع باز کردن سکشن `drawSection` رو صدا می‌زنه. رسم واقعی تو `drawSection`ه. پس هیچ کدی نباید فرض کنه DOM سکشن‌های بسته به‌روزه. قبلاً هر ۲۸ سکشن موقع لود (دوبار) رسم می‌شدن و کارت‌هاشون اندازه‌گیری می‌شد؛ لود تو تست ۱۳.۷ ثانیه → ۳ ثانیه شد.

| گزینه | کارش |
|---|---|

| `conversionCol` / `conversionLabel` | ستون و اسم نمایشی تبدیل اصلی |
| `cpaLabel` | مثلاً `CPI` |

| `rowFilter(row)` | قبل از هر چیزی ردیف خام شیت رو (هم مرجع هم هزینه) فیلتر می‌کنه. مثلاً `advertiserIs('65519')` برای Advertiser ID |

| `costPerMetrics` | کارت‌های «هزینه به ازای X» برای ستون‌های اضافه‌ی شیت مرجع: `{col, label, sinceFirst, campaignTable, countCard, noRate}`. `sinceFirst` = هزینه فقط از اولین روزی که این ستون پر شده حساب بشه (Signup رمزارز). `campaignTable` = تعداد/نرخ/هزینه به ازاش تو جدول کمپین هم بیاد. `countCard` = تعداد یه کارت جدا داشته باشه. `noRate` = ستون نرخ (X ÷ تبدیل اصلی) تو جدول نیاد (CTA Click آگاه) |

## ۴. قابلیت‌های سراسری

### تاریخ
- **امروز هیچ‌وقت حساب نمی‌شه.** ردیف‌های امروز و آینده موقع لود حذف می‌شن و حداکثر تاریخ دیروزه.
- پریست‌ها: **کل بازه | دیروز | از شنبه | هفته قبل | ۷ روز اخیر | ۳۰ روز اخیر**.
- **«هفته قبل»** (از ۲۶ اکتبر، `lastWeekWithin`، تو `index.html` و `report.html`): آخرین هفته‌ی کامل **شنبه تا جمعه** قبل از امروز، بر اساس تقویم نه شیت (۲۴ تا ۳۰ اکتبر هر روزی بزنی ← ۱۷ تا ۲۳ اکتبر؛ شنبه یعنی هفته‌ای که دیروز تموم شد). دو سرش داخل روزهایی که شیت داره می‌مونه (شیتی که چهارشنبه تموم شده: شنبه تا چهارشنبه)؛ اگه شیت تو اون هفته اصلاً دیتا نداره (ویپاد، توچال کافه بازار) خود هفته، خالی، نشون داده می‌شه نه یه بازه‌ی برعکس.
- «از شنبه» اگه امروز شنبه باشه، از **شنبه‌ی قبل** تا دیروز رو نشون می‌ده — یعنی روز شنبه با «۷ روز اخیر» یکیه (عرفان یه بار فکر کرد خرابه؛ بررسی شد و درست کار می‌کرد).
- تاریخ‌ها با تاریخ محلی ساخته می‌شن (`localIso`)، نه `toISOString`.

### فیلتر کمپین
- چندانتخابی، با **نوار جست‌وجو**؛ تو حالت جست‌وجو، تیک «همه» دقیقاً همون موارد منطبق رو انتخاب می‌کنه.
- **لیست‌ها از بقیه‌ی فیلترها پیروی می‌کنن** (`slotScope` / `scopedOptions`): لیست کمپین فقط کمپین‌های دارای دیتا در بازه‌ی تاریخ رو نشون می‌ده، مرتب بر اساس هزینه‌ی همون بازه (عدد کنار هر کمپین = هزینه‌ی بازه). اسنپ: دو لیست همدیگه رو فیلتر می‌کنن.
  - انتخاب‌ها نسبت به **کل** کمپین‌ها (`universe`) نگه داشته می‌شن؛ محدود شدن لیست انتخاب رو عوض نمی‌کنه.
  - کمپینی که دستی انتخاب شده (انتخاب ≤ نصف لیست) حتی بیرون از بازه تو لیست می‌مونه؛ انتخاب‌های «همه به‌جز چندتا» این‌طور نیستن.
- اسم کمپین تو جدول‌ها **کلیک‌پذیره** و داشبورد رو با همون کمپین فیلتر می‌کنه (کلیک دوباره = برداشتن فیلتر).

- هزینه چون فقط سطح کمپینه، **هزینه‌ی روزانه‌ی هر کمپین به نسبت نصب همون روز** بین Adgroup/Creativeها تقسیم می‌شه (`applySegFilter`). با یه مثال عدد به عدد با شیت چک شد.

### متن گزارش برای مشتری — `index.html` (از ۲۵ اکتبر)
- ته هر سکشن داشبورد اصلی یه کارت «متن گزارش برای مشتری» هست: یه `div` با `contenteditable` (قابل‌ویرایش) + دکمه‌ی «کپی متن». متن با هر رسم سکشن (`drawSection` → `renderClientMessage`) از نو ساخته می‌شه و ویرایش دستی رو پاک می‌کنه. `report.html` این کارت رو **نداره** (عرفان: فقط داشبورد اصلی).

- **قالب عرفان** (`buildClientMessage`): «سلام وقتتون بخیر» / «گزارش هفته پیش خدمت شما» (۱ روز: «گزارش دیروز…»، بقیه: «گزارش این بازه…») / بازه به شمسی بدون سال «(۲۶ مهر تا ۲ آبان)» / «مجموع» + خط‌ها / بعد برای هر گروه نوع کمپین «کمپین‌های X:» + همون خط‌ها / جمله‌ی مقایسه با بازه‌ی هم‌طول قبلی (`previousWindow`): «در هفته‌ی گذشته نسبت به هفته‌ی قبلش تعداد اکشن از A به B رسید و هزینه به ازای اکشن هم از C به D رسید.» (اگه یه طرف هزینه نداشت، نیمه‌ی دوم نمیاد). عددها با ارقام فارسی و جداکننده‌ی `,`، بدون «تومان»، مثل قالب.
- **خط‌ها** (`messageLines`): هزینه، نمایش، کلیک، نرخ CTR، تعداد سشن، نرخ STC، تعداد نصب، هزینه به ازای نصب، تعداد اکشن مدنظر، هزینه به ازای اکشن مدنظر. **خطی که کسب‌وکار اصلاً دیتاش رو نداره نمیاد** (`messageFields`: روی کل دیتای لودشده، نه فقط بازه؛ پس هفته‌ی بی‌دیتا ۰ نشون می‌ده). بعد از CTR/STC یه RLM (`‏`) هست وگرنه «٪» می‌پره قبل از CTR.
- **از کجا خونده می‌شن** (`messageSpec`): نمایش/کلیک از شیت هزینه (`impressions`/`clicks` حالا تو ردیف‌های join هم هستن). سشن: تبدیل اصلی اگه Sessions باشه (آگاه)، یا ستون «نصب» اگه Sessions باشه (شهر، فیروزه، تارا، تکنوپی)، یا Sessions شیت Blend Data (اسنپ‌ها). نصب: ستون نصب واقعی (Total Installs / Installs) یا تبدیل اصلی رمزارز. اکشن مدنظر: تبدیل اصلی؛ ولی اگه تبدیل اصلی سشن یا نصب باشه، اولین `costPerMetrics` (آگاه: CTA Click، رمزارز: Signup). اسنپ‌ها اکشن ندارن و جمله‌ی مقایسه روی سشنه. آگاه با `messageHide: ['clicks']` کلیک تبلیغ (و CTR و STC) رو نمیاره، هم‌راستا با داشبوردش؛ از ۲۵ اکتبر «هزینه به ازای سشن» هم داره (`messageSessionCost`) و اکشنش (CTA Click) «ایونت» نوشته می‌شه (`messageActionLabel`).
- **گروه‌های نوع کمپین** فقط از ستون `Campaign Type` شیت هزینه میاد (`normalizeCostRows` → `type`؛ `campaignTypeGroup`: اپلیکیشن → درون‌اپلیکیشنی، پویا/native → پویا، همسان، ویدیویی، پوش، پیامکی، پیام روبیکا، بنری). فقط **فیروزه، تارا، تکنوپی و آگاه** این ستون رو دارن؛ بقیه فقط «مجموع» دارن. گروه وقتی میاد که بازه حداقل دو نوع داشته باشه. برای بقیه، ستون Campaign Type باید به خروجی متابیس / `process.py` اون شیت‌ها اضافه بشه.
- **اسنپ‌پی** (`messageGroupBy: 'campaignName'`، خواسته‌ی عرفان ۲۵ اکتبر): به‌جای نوع کمپین، به تفکیک **Campaign Name** (مثلاً «Social Mehr 405:» بدون پیشوند «کمپین‌های»)، به ترتیب هزینه، فقط Campaign Nameهایی که فیلتر انتخاب کرده. اسنپ‌کب و اسنپ‌بیمه این رو ندارن.

- **موتور دیتا = خود `index.html`:** `slides.html` صفحه‌ی `/index.html?core` رو تو یه iframe مخفی باز می‌کنه؛ ته اسکریپت `index.html` اگه `window.frameElement` باشه و `?core` تو آدرس، به‌جای `init` فقط `window.dashCore` رو می‌ذاره (`PROJECTS`، `loadProject`، `messageRows`، `messageFields`، `campaignTypes`، `campaignTypeGroup`، `lastWeekWithin`، `weekStartFor`، `projectState` و…). پس هر پروژه/قانون/فیلتر کمپین جدید تو `index.html` **خودکار** تو اسلایدها هم هست (برخلاف `report.html`). ردیف‌ها از `messageRows` میان (همون منبع متن گزارش مشتری) که حالا `date` و `campaignLabel` هم داره. فقط پروژه‌ای که باز می‌شه لود می‌شه.
- **صفحه‌ها (hash):** `#` لیست مشتری‌ها (گزارش‌های ترکیبی بالا، بعد همه‌ی ۳۱ سکشن با لوگو + جست‌وجو) ← `#<id>` اسلایدها ← `#<id>/settings` تنظیمات. `#new-merge` ساختن گزارش ترکیبی، `#<merge-id>/parts` عوض کردن بخش‌هاش.
- **گزارش ترکیبی** (خواسته‌ی عرفان، مثلاً ارزپلاس وب + ارزپلاس اپ): چند سکشن داشبورد که ردیف‌هاشون با هم جمع می‌شه. تعریف‌ها تو `localStorage` کلید `slides:merges` (`{id:'merge-…', title, parts:[ids]}`). کلید کمپین‌هاش پیشوند بخش داره (`arzplus-web::sl-x`) تا کمپین‌های دو بخش قاطی نشن؛ بُعد تازه‌ی «بخش» فقط برای این گزارش‌هاست. بازه = اجتماع تاریخ بخش‌ها. اکشن = جمع اکشن هر بخش (اسمش «Purchase / Deposit (Web)» و از تنظیمات عوض می‌شه) — ترکیب یه بخش بی‌اکشن (مثلاً اسنپ) با بقیه، هزینه به ازای اکشن رو با هزینه‌ی اون بخش حساب می‌کنه. داده‌ی ساختار در کد: آبجکت report `{id, title, logo, theme, parts, merged}`؛ سکشن تکی هم یه report با یه بخشه.
- **ساختار پیش‌فرض (۷ اسلاید، به خواسته‌ی عرفان):** ۱ جلد (لوگو + عنوان + بازه‌ی شمسی) — ۲ «کمپین‌های اجرا شده» (**فقط لیست نوع کمپین‌ها، بدون هیچ عددی** — عرفان ۲۷ اکتبر؛ کاشی‌های شماره‌دار با یه خط توضیح اختیاری. تنظیم «چی لیست بشه»: مدیوم [پیش‌فرض] / Campaign Type خام شیت / اسم کمپین‌ها) — ۳ «آمار کلی کمپین‌ها» (کارت‌ها با درصد تغییر نسبت به بازه‌ی هم‌طول قبل) — ۴ «نمودار شماره ۱» (روزانه، هزینه ستونی + اکشن خطی) — ۵ «نمودار شماره ۲» (به تفکیک مدیوم: هزینه + هزینه به ازای اکشن؛ اگه فقط یه مدیوم باشه خطی روزانه‌ی هزینه به ازا) — ۶ «جدول مقایسه مدیوم‌ها» — ۷ «تحلیل کلی و اقدامات پیش رو» (دو ستون؛ اقدامات خالی).
  - **متن پیش‌فرض «تحلیل کلی» = تغییرهای اصلی نسبت به بازه‌ی هم‌طول قبل** (`analysisDraft`، عرفان ۲۷ اکتبر): «در هفته‌ی گذشته نسبت به هفته‌ی قبلش، هزینه از A به B رسید (X٪ کاهش)»، اکشن اصلی و هزینه به ازاش (از … به …)، نمایش/کلیک و CTR، سشن، مدیومی که اکشنش بیشترین تغییر رو داشت، کمپین‌های تازه و کمپین‌هایی که دیگه هزینه نداشتن (تا ۳ اسم). ۱ روزه: «دیروز/روز قبلش»، بقیه: «این بازه/بازه‌ی مشابه قبل». اگه بازه‌ی قبل دیتا نداشت، فقط خلاصه + «دیتایی برای مقایسه نیست».
  - اکشن اصلی به ترتیب: اکشن (`messageSpec`) ← نصب ← سشن ← کلیک؛ هزینه به ازاش CPA/CPI/هزینه به ازای سشن/CTR. اسنپ‌ها (budget) اکشن ندارن ← سشن. فیلتر کمپین پیش‌فرض همون `defaultCampaigns` داشبورده (اسنپ‌ها روی Campaign Name).
- **متریک‌ها:** هزینه، نمایش، کلیک، CTR، سشن، هزینه به ازای سشن، STC، نصب، CPI، اکشن، CPA، سهم از هزینه (فقط جدول/نمودار). فقط چیزهایی که اون کسب‌وکار دیتاش رو داره (`messageFields`). اسم اکشن پیش‌فرض `conversionLabel` (یا اولین `costPerMetrics` برای سشن/نصب‌محورها)؛ از تنظیمات عوض می‌شه. **بُعدها:** روز، هفته (شنبه)، کمپین، مدیوم (+ Campaign Name برای اسنپ‌ها).
- **مدیوم:** (۱) چیزی که عرفان تو تنظیمات برای اون کمپین نوشته، (۲) ستون `Campaign Type` شیت هزینه با `campaignTypeGroup` (فیروزه، تارا، تکنوپی، آگاه)، (۳) **حدس از اسم کمپین** (`guessMedium`: inapp→درون‌اپلیکیشنی، push→پوش، sms→پیامکی، vid→ویدیویی، bnr→بنری، native→پویا، cafe/cb→کافه بازار…)، (۴) «سایر». بقیه‌ی پروژه‌ها Campaign Type ندارن پس مدیومشون حدسیه؛ قبل از فرستادن گزارش چک بشه.
- **کمپین‌های هر اسلاید** (عرفان ۲۷ اکتبر): تو تنظیمات هر اسلاید «مثل کل گزارش» یا «انتخاب دستی برای همین اسلاید» با چک‌لیست (`slide.campaigns`، آرایه‌ی کلید). کارت‌ها، جدول، نمودار، لیست نوع کمپین و متن تحلیل همون اسلاید (با بازه‌ی قبلش) فقط همون کمپین‌ها رو می‌شمرن (`dataFor(s)`، کش‌شده). بالای اسلاید «N کمپین انتخابی» نوشته می‌شه.
- **رنگ‌بندی** (عرفان ۲۷ اکتبر، تنظیمات → «عنوان و ظاهر»): «رنگ برند» (پیش‌فرض، از `theme` همون سکشن / بخش اول گزارش ترکیبی)، ۱۰ پالت آماده (`THEME_PRESETS`: فیروزه‌ای، آبی، سرمه‌ای، سبز، بنفش، صورتی، قرمز، نارنجی، طلایی، خاکستری) یا «دلخواه» با دو `input type=color`: رنگ اصلی و رنگ دوم (سری دوم نمودار؛ پیش‌فرض `#1B1F27`). ذخیره تو `cfg.theme` (`{preset, accent, second}`، null = برند) پس با قالب/سرور هم میاد. `paletteTheme` ازش همون شکل `BRANDS` رو می‌سازه: ink = رنگ اصلی تیره‌شده (۲۰٪، برای رنگ روشن با روشنایی >۰.۶: ۴۵٪)، soft = همون رنگ با شفافیت ۰.۱۲ (روشن: ۰.۲)، گرادیان رنگ اصلی ← ink. روی همه‌ی اسلایدها (پنل جلد، نوار تیتر، سرستون جدول، کارت‌ها، کاشی‌ها، نمودارها)، رنگ پس‌زمینه‌ی صفحه و خروجی PDF/HTML اثر داره. یه پیش‌نمایش کوچیک کنار رنگ‌ها هست.
- **تنظیمات هر مشتری:** بازه (هفته قبل [پیش‌فرض] / ۷ روز / ۳۰ روز / از شنبه / دیروز / کل / دلخواه با تاریخ)، روشن/خاموش مقایسه با بازه‌ی قبل، عنوان گزارش، برچسب جلد، اسم اکشن، لوگو (آپلود، کوچیک‌شده تا ۴۸۰px)، تیک کمپین‌ها (لیست به ترتیب هزینه‌ی بازه) + مدیوم هر کمپین، و برای هر اسلاید: نمایش، عنوان، متریک‌ها، بُعد، نوع نمودار (ستونی+خطی، ستونی، ستونی افقی، خطی، دایره‌ای)، حداکثر ردیف، تعداد ستون متن، جابه‌جایی، کپی، حذف، و افزودن اسلاید (نمودار، جدول، کارت‌ها، کمپین‌ها، متن). خروجی/ورود JSON تنظیمات.
- **ویرایش روی اسلاید:** هر متن/عدد/سرستون/خانه‌ی جدول (`data-k`) `contenteditable`ه؛ پیست فقط متن ساده. کلیک روی لوگو = عوض کردنش. ✕ کنار ردیف جدول = حذف اون ردیف از اسلاید (مجموع همون مجموع کل می‌مونه). نوار بالای هر اسلاید: جابه‌جایی، پنهان، برگردوندن ویرایش‌ها، تنظیمات، ارائه از همون‌جا. دکمه‌ی «ویرایش» حالت ویرایش رو خاموش/روشن می‌کنه؛ «بازسازی» همه‌ی ویرایش‌های این بازه رو پاک می‌کنه.
- **ذخیره‌ی مشترک روی سرور** (عرفان ۲۷ اکتبر: «با دو مرورگر لاگین می‌کنم نسخه‌ی ویرایش‌شده رو نمی‌بینم»): `api/store.js` همه‌چیزِ گزارش‌ها رو تو **یه Google Sheet** نگه می‌داره که Service Account (`data-entry-automation@data-entry-506107.iam.gserviceaccount.com`) **Editor**ـشه — تب اول، هر کلید یه ردیف: A کلید، B زمان، C کاربر، D تا Z مقدار JSON تیکه‌تیکه (۴۵ هزار کاراکتر، چون لوگو بزرگه؛ حداکثر ~۱ مگ). کلیدها: `<report>|cfg`، `<report>|edits|<from>-<to>`، `_|merges`. `GET /api/store?prefix=<report>|` همه‌ی کلیدهای یه گزارش؛ `POST {items:[{key, value}]}` (value=null یعنی حذف: ردیف خالی می‌شه). بدون ورود 401. scope این endpoint نوشتنیه (`spreadsheets`)، `sheet-data.js` همچنان فقط خوندنی.
  - **آیدی شیت:** ثابت `STORE_SPREADSHEET_ID` بالای `api/store.js` (یا متغیر محیطی `STORE_SPREADSHEET_ID` تو Vercel). **تا ۲۷ اکتبر خالیه** — ساختن شیت از محیط ابری اجازه نگرفت؛ عرفان باید یه شیت خالی بسازه، با ایمیل Service Account به‌عنوان Editor شیر کنه و لینکش رو بده. تا اون موقع API 503 `no_store` می‌ده و صفحه می‌نویسه «ذخیره‌ی مشترک هنوز وصل نشده — فقط تو همین مرورگر» و مثل قبل با `localStorage` کار می‌کنه. شیت شیر نشده: 403 `no_access`.
  - **رفتار صفحه:** `localStorage` همچنان کپی محلیه و صفحه از اون می‌خونه. موقع باز شدن هر گزارش `remoteLoad('<id>|')` (و موقع لود `_|merges`): نسخه‌ی سرور برنده‌ست؛ کلیدهایی که فقط این مرورگر داره **فقط بار اولی** که اون گزارش تو این مرورگر همگام می‌شه بالا می‌رن (ویرایش‌های قبل از سرور)، بعدش کلیدی که سرور نداره یعنی جای دیگه حذف شده و اینجا هم پاک می‌شه (`slides:synced`). هر `store.set/del` تو صف می‌ره و **۲.۵ ثانیه بعد از آخرین تغییر** با یه POST فرستاده می‌شه (سهمیه‌ی ۶۰ درخواست در دقیقه‌ی Service Account، مشترک با خوندن شیت‌ها)؛ «ذخیره قالب» فوری؛ موقع بستن/پنهان شدن صفحه هم. خطا = تلاش دوباره ۱۵ ثانیه بعد. وضعیت تو نوار بالا: «در حال ذخیره…» / «ذخیره شد — ساعت» / خطا.
  - همگام‌سازی زنده نیست: مرورگر دوم تغییر رو موقع باز کردن (یا رفرش) گزارش می‌بینه؛ دو نفر همزمان روی یه گزارش = آخری برنده‌ست.
  - تست: `api/store.js` با یه `google-auth-library` جعلی (Sheets در حافظه) با Node؛ صفحه با دو context جدای Playwright که `/api/store` رو به یه Map مشترک route می‌کنن.
- **ذخیره و قالب:** تنظیمات با کلید `slides:cfg:<id>` (خودکار)، ویرایش‌های روی اسلاید با `slides:edits:<id>:<from>-<to>` (پیش‌نویس، خودکار، **برای هر بازه جدا**) — هم `localStorage` هم سرور (بالا).
  - **دکمه‌ی «ذخیره قالب»** (عرفان ۲۷ اکتبر: «ادیت کنم و به‌عنوان قالب اون مشتری ذخیره کنم» و بعد: «همه‌ی ادیت‌هام بمونه»): **همه‌ی ویرایش‌های متنی** — عنوان‌ها، زیرعنوان‌ها، سرستون‌ها، اسم کارت‌ها، اسم ردیف‌های جدول (`c:<row>:name`)، متن تحلیل (حتی ستون خودکار)، اقدامات، توضیح نمودار، کاشی‌های نوع کمپین، ردیف‌های حذف‌شده، همه‌ی متن‌های جلد — از ویرایش‌های این بازه منتقل می‌شن به `cfg.tpl[slideId]` و تو همه‌ی بازه‌های بعدی می‌مونن (`isTemplateKey`). **فقط عددهای کارت‌ها و خونه‌های جدول** (`v:`، `d:`، `c:<row>:<metric>`) تو قالب نمی‌رن و فقط برای همون بازه می‌مونن، چون هفته‌ی بعد غلط می‌شن. پس اگه زیرعنوان (خط بازه) یا متن تحلیل که عدد داره ویرایش و ذخیره بشه، هفته‌ی بعد همون متن قدیمی میاد — با دکمه‌ی «پیش‌فرض» برمی‌گرده. ترتیب اعمال: قالب، بعد ویرایش این بازه. «بازسازی» فقط ویرایش‌های ذخیره‌نشده‌ی این بازه رو پاک می‌کنه؛ «پاک کردن متن‌های قالب» تو تنظیمات. دکمه بعد از اولین ذخیره سبز می‌شه. اسلاید ویرایش‌شده برچسب «ویرایش‌شده» داره.
  - **دکمه‌ی «پیش‌فرض» هر اسلاید** (بالای اسلاید و تو تنظیماتش، عرفان ۲۷ اکتبر): اسلاید رو برمی‌گردونه به نسخه‌ی اول — متن‌ها (قالب + این بازه) و تنظیماتش (متریک، بُعد، نمودار، کمپین‌ها؛ برای ۷ اسلاید اصلی از `defaultSlides`، بقیه از `newSlide` همون نوع)؛ جا و نمایش/پنهان اسلاید عوض نمی‌شه (`resetSlide`). جای دکمه‌ی قبلی «برگردوندن ویرایش‌های این بازه» رو گرفت.
- **ارائه:** تمام‌صفحه، یه اسلاید در هر لحظه؛ ← / Space / کلیک بعدی، → قبلی، Esc خروج.
- **اسم فایل خروجی** (عرفان ۳۱ اکتبر، `fileBase`): «گزارش کمپین <اسم مشتری> - <بازه>»، مثلاً «گزارش کمپین بانکینو - 2 تا 8 آبان» — روز با رقم لاتین، ماه شمسی، بدون سال؛ ماه مشترک یه‌بار («28 مهر تا 4 آبان» اگه دو ماه، «4 آبان» اگه یه روز). اسم مشتری = اسم سکشن/گزارش ترکیبی (نه متن ویرایش‌شده‌ی جلد). برای PDF و HTML. تو تست Playwright بدون `LANG=C.UTF-8` اسم فارسی دانلود «download» می‌شه — مشکل محیطه نه کد.
- **PDF:** اسلایدها (عکس‌شده: نمودارها PNG) تو `#printDeck` و `print()` مرورگر؛ `@page{size:1280px 720px}` یعنی هر اسلاید یه صفحه‌ی ۱۶:۹. **HTML:** یه فایل مستقل (`<id>-slides-<from>-<to>.html`) با CSS اسلاید (`<style id="slideCss">`)، نمودارها عکس، بدون ویرایش، اسلایدها با عرض پنجره کوچیک می‌شن و چاپش هم صفحه‌به‌صفحه‌ست.
- **اندازه‌ی اسلاید** همیشه ۱۲۸۰×۷۲۰؛ رو صفحه با `transform: scale(--k)` به عرض قاب کوچیک می‌شه (موبایل هم). عدد کارت یا متن تحلیل اگه جا نشه کوچیک می‌شه (`fitSlideText`).
- چک‌شده با Python روی شیت تکنوپی (۱۷ تا ۲۳ اکتبر): هزینه ۶۷,۵۵۰,۴۰۶، نمایش ۵,۹۸۰,۵۱۴، کلیک ۹,۹۱۶، سشن ۶,۲۰۳، Validation ۴۱، مدیوم‌ها (درون‌اپلیکیشنی ۵۵,۵۳۰,۹۰۰، پوش ۷,۴۷۴,۴۰۰…) و تغییر CPA نسبت به هفته‌ی قبل (+۱۴۵.۴٪).

### موبایل (≤۶۴۰px)
- تب‌ها و زیرتب‌ها یک خط با اسکرول افقی و sticky. کارت‌ها دوتا دوتا؛ تکِ آخر تمام‌عرض. جدول‌ها اسکرول افقی با ستون اسم ثابت. دراپ‌داون‌ها (کمپین و فیلتر Source/Term/Content) تمام‌عرض.

## ۶. نکات فنی و تله‌ها

- **`[hidden]` با `display:flex` کار نمی‌کنه:** قانون صریح `X[hidden]{display:none}` لازمه.
- `transform` روی المان inline کار نمی‌کنه (فلش دکمه‌ی بستن) → `display:inline-block`.
- `renderKpiCards` تعداد ستون‌ها رو inline می‌نویسه، پس مدیا کوئری موبایل `!important` لازم داره.
- متن ترکیبی فارسی/لاتین با درصد (مثل «اختلاف با یکتانت: +12٪») ترتیبش به هم می‌ریزه → `<bdi dir="ltr">` دور عدد، و اسم منبع فارسی.
- اسم‌های فارسی رو با فونت mono نشون نده. IBM Plex Mono حروف فارسی نداره؛ از ۹ اکتبر `--font-mono` بعدش `Vazirmatn` داره تا «تومان» و متن فارسی داخل عددها از هم باز نشه. ولی باز هم متن فارسی رو عمداً mono نکن.
- **عدد علامت‌دار وسط متن فارسی** علامتش می‌پره اون‌ور («12-»). برای `+`/`−` از `fmtSigned(n)` استفاده کن (خروجیش `<bdi dir="ltr">`ه)؛ عدد کارت‌های KPI هم تو `kpiValueHtml` با `<bdi>` ایزوله شده. `.di-tag` چون `inline-flex`ه فاصله‌ها رو می‌خوره — `gap` داره.
- **اسم ستون نمایش/کلیک فرق داره:** `Cost - Yektanet` طلاین، `Yektanet` بلو و بلو جونیور و تب‌های طلاسی `Impressions`/`Clicks` (جمع) دارن؛ بقیه `Impression`/`Click`. طلاین و بلو جونیور تا ۲۵ اکتبر اشتباهی مفرد تنظیم شده بودن (جایی نمایش داده نمی‌شد پس دیده نشد)؛ با متن گزارش مشتری درست شدن.
- اسم تب‌های شیت دقیق‌ان: `Arzplus- Yektanet` و `Ramzarz- Yektanet` قبل از خط تیره فاصله ندارن. توچال `Tocal` نوشته شده.
- لیست فیلتر کمپین، بدون `includeUnmatchedCost`، فقط کمپین‌های طرف تبدیل رو نشون می‌ده؛ و جدول کمپین هزینه‌ی یه کمپین رو فقط روزهایی که ردیف تبدیل داره حساب می‌کنه (مثلاً `cb-dc-rtg` تو ۷ روز اخیر نیومد چون App Metrica ردیف نداشت).
- **`/api/sheet-data`:** جواب فشرده‌ست: `{headers, rows}` (ردیف‌ها آرایه، ردیف‌های کاملاً خالی حذف). **از ۲۴ اکتبر چند تب با هم:** `sheet` تکراری (`?spreadsheetId=…&sheet=A&sheet=B`) → `{sheets: {A: {headers, rows}, B: …}}`، با یه `values:batchGet` (گوگل یه درخواست حساب می‌کنه). یه `sheet` → همون `{headers, rows}`. `fetchSheetData` تو مرورگر درخواست‌های همون لحظه رو برای هر اسپردشیت جمع می‌کنه (`sheetQueue`/`flushSheetQueue`) و `sheetRows` فرمت قدیمی `{data}` رو هم قبول می‌کنه (mockهای تست). **از ۲۶ اکتبر (ورود) کش لبه‌ی Vercel خاموشه:** `Cache-Control: private, max-age=120` — کش لبه فقط روی URL کلید می‌خورد و دیتا رو به کسی که وارد نشده هم می‌داد؛ حالا فقط مرورگر خود کاربر ۲ دقیقه نگه می‌داره. (قبلش `s-maxage=300` بود.) هر نمونه‌ی گرم تابع هم ۲ دقیقه کش حافظه داره (`memo`) و موقع خطای سهمیه تا ۲۴ ساعت نسخه‌ی قبلی رو برمی‌گردونه.
- **سهمیه‌ی Google Sheets API:** ۶۰ درخواست خوندن در دقیقه برای Service Account. قبلاً هر لود ~۳۸ درخواست بود و با دو سه بار رفرش (یا بعد از هر دیپلوی که کش لبه رو خالی می‌کنه) خطای `Quota exceeded … Read requests per minute per user` می‌داد؛ الان هر لود ۱۹ درخواسته (یکی به ازای هر اسپردشیت + تب‌های Source/Term/Content). API روی 429 دو بار دیگه (۱.۵ و ۳ ثانیه بعد) تلاش می‌کنه و بعد `{code:'quota'}` با 429 برمی‌گردونه؛ سکشن پیام «سهمیه‌ی خوندن گوگل شیت پر شده — رفرش کن» نشون می‌ده نه «شیت رو شیر کن». اگه یه تب از یه اسپردشیت خطا بده، همه‌ی تب‌های اون اسپردشیت تو همون لود خطا می‌گیرن.
- `fmtNum` فرمت‌کننده‌ی `Intl.NumberFormat` رو کش می‌کنه (`toLocaleString` هر بار یه فرمت‌کننده‌ی تازه می‌ساخت). انیمیشن Chart.js ۳۰۰ میلی‌ثانیه‌ست (`makeChart`). `fitKpiValues` اندازه‌گیری‌ها رو دسته‌ای انجام می‌ده.
- **`route()` تو `slides.html` هر بار آبجکت report تازه می‌سازه**؛ اگه همون گزارش بازه، آبجکت قبلی (که `minDate`/`maxDate` داره) نگه داشته می‌شه — وگرنه صفحه‌ی تنظیمات با خطا خالی می‌موند.
- **iframe هسته‌ی `slides.html`:** چیزی که `index.html` تو حالت `?core` به `window.dashCore` می‌ده قرارداد بین دو صفحه‌ست؛ اسم این تابع‌ها رو عوض کردی، اونجا هم عوض کن. `messageRows` باید `date` و `campaignLabel` رو نگه داره (نمودار روزانه و جدول کمپین اسلایدها بهش وابسته‌ان).
- **Chart.js زیر `transform: scale`:** نمودار responsive اندازه رو از `getBoundingClientRect` (اندازه‌ی کوچیک‌شده) می‌خونه و روی گوشی یه‌چهارم کشیده می‌شد؛ تو `slides.html` نمودارها `responsive:false` با اندازه‌ی `offsetWidth/Height` قابِ ۱۲۸۰تایی‌ان.
- **چاپ و `transform`:** کروم موقع صفحه‌بندی چاپ موقعیتِ بدون transform رو می‌بینه؛ وسط‌چین کردن جلد با `translateY(-50%)` باکس تاریخ رو هل می‌داد به صفحه‌ی بعد. تو اسلایدها برای وسط‌چین از flex استفاده کن، نه transform.
- **محیط ابری:** به `docs.google.com`، `cdnjs` و `*.vercel.app` دسترسی نیست (پروکسی می‌بنده). سایت زنده قابل تست نیست. شیت‌ها با **Google Drive MCP** خونده می‌شن: `download_file_content` با `exportMimeType` xlsx → فایل base64 تو tool-results → decode و با `openpyxl` بخون. `read_file_content` برای شیت‌های کوچک کافیه؛ `get_file_metadata` با `MAX_ALLOWED` برای دیدن اسم تب‌ها و هدرها (خالی‌ها رو حذف می‌کنه).
- **روش تست:**
  - اسکریپت بزرگ HTML رو جدا کن → `node --check`.
  - Chart.js رو با `npm pack chart.js@4.4.1` بگیر (npm در دسترسه).
  - Playwright (`/opt/node-tools/node_modules/playwright`، Chromium در `/opt/pw-browsers/chromium`) روی `python3 -m http.server 8765`.
  - `**/api/sheet-data*` با `mock.json` (کلید `spreadsheetId||sheet`، ساخته‌شده از xlsx واقعی) جواب داده می‌شه؛ cdnjs با فایل محلی؛ فونت‌ها abort.
  - `timezoneId:'Asia/Tehran'` و `page.clock.install` برای تست تاریخ‌ها.
  - کپی: `navigator.clipboard` رو stub کن.
  - برای قوانین جدید، جواب درست رو جدا با Python از xlsx حساب کن و عدد به عدد مقایسه کن.
  - رگرسیون: هر ۳۱ سکشن رندر بشن، بدون خطای صفحه، دسکتاپ (1400) و موبایل (390). چون سکشن‌ها فقط وقتی باز می‌شن رسم می‌شن، تست باید روی تک‌تک تب‌ها و زیرتب‌ها کلیک کنه و بعد متن سکشن رو بخونه.
  - **روی ویندوز (دسکتاپ عرفان، بدون node):** یه سرور Python کوچیک که فایل‌های ریپو رو سرو می‌کنه و `/api/*` رو به `https://yektanet-pulse-dashboard.vercel.app` پروکسی می‌کنه، تو مرورگر داخلی اپ. دیتای واقعی می‌ده، بدون mock. اسکریپتش رو بیرون ریپو نگه دار.
  - برای مقایسه‌ی قبل/بعد: `git worktree add` از `origin/main` روی یه پورت دیگه، با همون mock، متن همه‌ی سکشن‌ها رو مقایسه کن.
  - `pkill -f "http.server"` رو تو همون دستوری که الگوش توشه نزن — خود شل رو می‌کشه.

31. **کارت «متن گزارش برای مشتری»** ته هر سکشن داشبورد اصلی، با قالب عرفان (مجموع، گروه‌های نوع کمپین، مقایسه با بازه‌ی قبل) و دکمه‌ی کپی (بخش ۴). ستون Campaign Type خونده می‌شه؛ نمایش/کلیک طلاین و بلو جونیور درست شد.

33. عددهای متن گزارش مشتری بولد شدن (صفحه: `<b>`؛ کپی: HTML + `**…**` برای تلگرام).
34. متن گزارش آگاه: «هزینه به ازای سشن» اضافه شد و «اکشن مدنظر» → «ایونت».
35. **اپ طلاسی و اپ نقره‌سی** (مثل رمزارز نیوز: CPI + Verification، درون اپلیکیشن / کافه بازار) با گزینه‌ی تازه‌ی `campaignKey` (بخش ۳ طلاسی). ۳۱ سکشن.

**۲۶ اکتبر ۲۰۲۶**
36. پریست **«هفته قبل»** (شنبه تا جمعه‌ی هفته‌ی گذشته) به همه‌ی داشبوردها، هم `index.html` هم `report.html`.
37. پیش‌فرض اسنپ‌بیمه = `Campaign October 2026`.
38. **۲۶ اکتبر — ورود (لاگین)** برای داشبورد و گزارش هفتگی: حساب‌ها تو `DASHBOARD_USERS`، کوکی امضاشده‌ی ۳۰ روزه، API دیتا بدون ورود 401؛ کش لبه‌ی API خاموش شد (بخش ۱ «ورود»).

**۲۷ اکتبر ۲۰۲۶**
39. **گزارش اسلایدی `slides.html`:** گزارش هفتگی مشتری به شکل ۷ اسلاید (جلد، کمپین‌های اجرا شده، آمار کلی، دو نمودار، مقایسه‌ی مدیوم‌ها، تحلیل و اقدامات)، صفحه‌ی تنظیمات هر مشتری، ویرایش مستقیم همه‌ی متن‌ها، حالت ارائه، خروجی PDF و HTML. دیتا از `index.html?core` (بخش ۴ «گزارش اسلایدی»).
40. گزارش اسلایدی: **دکمه‌ی «ذخیره قالب»**، اسلاید «کمپین‌های اجرا شده» فقط لیست نوع کمپین‌ها، **کمپین‌های جدا برای هر اسلاید**، متن پیش‌فرض «تحلیل کلی» = مقایسه با بازه‌ی قبل، **گزارش ترکیبی** چند سکشن (مثلاً ارزپلاس وب + اپ).
41. بلو: کمپین‌های `inapp-cpc-shareit`، `lba-bazar` و `bj-inapp-cpi` حذف شدن (`BLUE_DROPPED` + همه‌ی `bj`)، تو `index.html` و `report.html`. (`slides.html` دیتا رو از `index.html` می‌گیره پس خودش اعمال می‌شه.)
42. گزارش اسلایدی: قالب حالا همه‌ی ویرایش‌های متنی (شامل تحلیل) رو نگه می‌داره، فقط عددها نه؛ دکمه‌ی **«پیش‌فرض»** برای هر اسلاید.
43. گزارش اسلایدی: **ذخیره‌ی مشترک روی سرور** (`api/store.js` + یه Google Sheet) تا همه‌ی مرورگرها یه نسخه ببینن؛ منتظر شیت ذخیره از عرفان.

45. **۳۱ اکتبر** — گزارش اسلایدی: اسم فایل خروجی PDF/HTML «گزارش کمپین <مشتری> - 2 تا 8 آبان».

**۲۸ اکتبر ۲۰۲۶**
45. کارت «متن گزارش برای مشتری» داشبورد اصلی **پیش‌فرض بسته** شد (دکمه‌ی نمایش/بستن).
46. پیش‌فرض اسنپ‌کب = فقط `Snapp City - Oct 2026` (جای Bike و Pickup).
47. **طلاین:** وب و نمای کلی از ۲۳ اکتبر تبدیل وب رو از `Web - Total` (KYC) می‌خونن؛ **CPA بازنویسی شد** — KYC از `Web - Total` (فقط `cpa-`)، Panel Cost از `CPA Panel`، Cost = KYC × ۲۵۰,۰۰۰ و سود. گزینه‌های تازه: `from`/`before` روی `refSheet`، `costCol`، `costLabel`، `dealPrice`. با دیتای واقعی تست نشده (بخش ۳ طلاین).

### کارهای باز
- **ظاهر اسلایدها مطابق نمونه‌ی عرفان** (`Report.html` رو کامپیوترش): فایل باید تو ریپو (یا چت) بیاد تا طراحی دقیقاً مثل اون بشه. (منتظر عرفان)
- **شیت ذخیره‌ی گزارش اسلایدی:** عرفان یه Google Sheet خالی بسازه، با `data-entry-automation@data-entry-506107.iam.gserviceaccount.com` به‌عنوان Editor شیر کنه و لینک بده؛ آیدیش تو `STORE_SPREADSHEET_ID` در `api/store.js` بره. (منتظر عرفان)
- مدیوم پروژه‌هایی که ستون Campaign Type ندارن حدس از اسم کمپینه؛ اضافه شدن ستون به خروجی متابیس دقیقش می‌کنه.
- **توچال کافه بازار:** `cb-bulk` و `cb-dc` (اردیبهشت–خرداد) دیتای تبدیل ندارن — نمایش فقط هزینه، یا خوندن از `Tocal - Metrix - Old`؟ (منتظر تصمیم عرفان)

- اگه پروژه‌ی جدیدی اضافه شد، یادآوری شیر کردن شیت با Service Account.
